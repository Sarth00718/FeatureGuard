================================================================================
  FEATUREGUARD – STEP BY STEP EXECUTION GUIDE
  MLOps project covering Practicals 1-10
================================================================================

WHAT THIS PROJECT DEMONSTRATES
────────────────────────────────
  P1  Git / GitHub          – version control, .gitignore, .env not committed
  P2  Deployment            – FastAPI (replaces Flask), Nginx reverse proxy
  P3  Containerisation      – Dockerfile (single + multistage), Docker Compose,
                              volumes, named networks (driver: bridge), depends_on
  P4  ML Pipeline           – sklearn Pipeline (scaler + RandomForest), DVC stages
  P5  CI/CD (Jenkins)       – Declarative pipeline, Windows bat steps, quality gate,
                              smoke test, deploy, explicit rollback on failure
  P6  MLflow                – experiment tracking, model registry, quality gate
  P7  Prometheus            – /metrics endpoint, custom counters + histogram scraped
  P8  Grafana               – provisioned dashboard (no manual import needed)
  P9  Kubernetes (deploy)   – Deployments, Services, ConfigMap, Ingress, probes
  P10 Kubernetes (rollback) – rollout undo, rollback-demo.ps1

PHASE 1 – ML PIPELINE  (Practical 4 + 6)
================================================================================

Step 1-A  Download the dataset (DVC-tracked, Practical 4)
──────────────────────────────────────────────────────────
  python ml\download_data.py

  → writes data\raw\winequality-red.csv
  This file is DVC-tracked (data\raw\winequality-red.csv.dvc); only the pointer
  goes into git, not the data itself (Practical 1 large-file hygiene).

Step 1-B  Validate the data schema
───────────────────────────────────
  python -m ml.validate_data

  → checks that all 12 expected columns are present and numeric.
  Exits with code 1 if the schema is wrong (fail-fast before training).

Step 1-C  Run the full DVC pipeline (train + evaluate)
──────────────────────────────────────────────────────
  dvc repro

  Stages defined in dvc.yaml:
    validate_data  →  ml/validate_data.py
    preprocess     →  ml/preprocessing.py   (builds reference.csv for drift)
    train          →  ml/train.py           (logs to MLflow, saves models/)
    evaluate       →  ml/evaluate.py        (quality gate: min_r2, max_rmse)

  Alternatively run training directly:
    python -m ml.train

  QUALITY GATE: if the trained model is below the thresholds in params.yaml
  (min_r2=0.45, max_rmse=0.80) the script exits with code 1 and Jenkins will
  not build or deploy. This is Practical 5 / 6 integration.

  MLflow UI (Practical 6):
    mlflow ui --backend-store-uri sqlite:///mlflow.db
    → open http://localhost:5000 to see runs, params, metrics, model registry.

  After training you should see:
    models\model.joblib
    models\metadata.json
    models\reference.csv

PHASE 3 – DOCKER COMPOSE  (Practical 3 + 7 + 8)
================================================================================

Step 3-A  Build and start all services
───────────────────────────────────────
  From the repository root:

  docker compose --env-file .env -f deployment\docker-compose.yml up -d --build

  Services started (Practical 3 – multi-service Compose):
    postgres       – PostgreSQL 16 (named volume pgdata, healthcheck)
    backend        – FastAPI / uvicorn  (depends_on postgres healthy)
    frontend       – React SPA (multistage build: node → nginx)
    nginx          – Reverse proxy  (port 80 → frontend / backend)
    mlflow         – MLflow tracking server  (port 5000)
    prometheus     – Metrics scraper  (port 9090)
    grafana        – Dashboards  (port 3000, auto-provisioned)

  Named network: appnet  (driver: bridge) – Practical 3 networking concept.
  Named volumes: pgdata, mlflowdata, promdata, grafanadata, jenkinshome
                 – Practical 3 volume persistence concept.

Step 3-B  Verify everything is up
──────────────────────────────────
  docker compose -f deployment\docker-compose.yml ps

  All services should show "healthy" or "running".

Step 3-C  Open the application
───────────────────────────────
  Browser → http://localhost/           React frontend via Nginx
  Browser → http://localhost/api/health FastAPI health (Nginx strips /api/)
  Browser → http://localhost:5000       MLflow UI
  Browser → http://localhost:9090       Prometheus (query: featureguard_*)
  Browser → http://localhost:3000       Grafana  (admin/admin → FeatureGuard dashboard)

Step 3-D  Make predictions and watch metrics
────────────────────────────────────────────
  Use the React UI at http://localhost/ – fill in the wine features and click Predict.

  Or POST directly:
    curl -X POST http://localhost/api/predict ^
         -H "Content-Type: application/json" ^
         -d "{\"fixed_acidity\":7.4,\"volatile_acidity\":0.7,\"citric_acid\":0.0,\"residual_sugar\":1.9,\"chlorides\":0.076,\"free_sulfur_dioxide\":11,\"total_sulfur_dioxide\":34,\"density\":0.9978,\"ph\":3.51,\"sulphates\":0.56,\"alcohol\":9.4}"

  Send ~30 requests to trigger a drift batch check.
  Prometheus → Grafana shows counters updating in real time (Practical 7 + 8).

Step 3-E  Trigger drift detection manually
───────────────────────────────────────────
  curl -X POST http://localhost/api/drift/check

  → runs the KS-test batch comparison against reference.csv; result visible in
    the Grafana dashboard and at GET /api/drift/alerts.

Step 3-F  Tear down
────────────────────
  docker compose -f deployment\docker-compose.yml down      # keep volumes
  docker compose -f deployment\docker-compose.yml down -v   # also delete volumes

    Expiry   : 90 days (or No expiration for a demo machine)

  → Generate token → COPY IT NOW (shown only once)

───────────────────────────────────
  Open PowerShell, cd to the project:

    cd C:\Users\SARTH\OneDrive\Desktop\MLOps\FeatureGuard

    git init

    git commit -m "Initial commit - FeatureGuard MLOps project"

    git remote add origin https://github.com/Sarth00718/FeatureGuard.git

    git push -u origin main
      # Enter your GitHub username when prompted
      # Enter your PAT as the password (not your GitHub password)

  After the push, verify at https://github.com/Sarth00718/FeatureGuard that:
    ✔ Jenkinsfile is in the root
    ✔ .env is NOT present (only .env.example)

PHASE 4 – JENKINS CI/CD PIPELINE  (Practical 5 scenario3 – GitHub SCM)
================================================================================

  Your Jenkins is already running locally at http://localhost:8080.
  The Jenkins Docker container in docker-compose.yml has been removed to avoid
  a port conflict. You do NOT need to start any extra service for Jenkins.

Step 4-A  Install required Jenkins plugins  (skip if already installed)
────────────────────────────────────────────────────────────────────────
  Jenkins → Manage Jenkins → Plugins → Available plugins
  Search and install (restart Jenkins after):
    ✔ Pipeline               (if not already present)
    ✔ Pipeline: Stage View   (shows stage-by-stage UI)
    ✔ Git                    (SCM integration)
    ✔ JUnit                  (publishes pytest.xml results)
    ✔ Credentials Binding    (withCredentials step)

Step 4-B  Add credentials to Jenkins
──────────────────────────────────────
  Jenkins → Manage Jenkins → Credentials → System → Global credentials → Add

  ID                   Kind                  Value
  ─────────────────    ──────────────────    ────────────────────────────────────
  github-pat           Username+password     Username = your GitHub username
                                             Password = your PAT (from Step G-2)
  featureguard-env     Secret file           your FeatureGuard\.env (real passwords)
  featureguard-kube    Secret file           %USERPROFILE%\.kube\config
                                             (only needed for DEPLOY_TARGET=kubernetes)

Step 4-C  Create the pipeline job
──────────────────────────────────
  GitHub (like Practical 5 scenario3 – Pipeline Script from SCM):

    Jenkins → New Item → type "Pipeline" → name "FeatureGuard" → OK

    Under "Pipeline":
      Definition     : Pipeline script from SCM
      SCM            : Git
      Repository URL : https://github.com/<YOUR_USERNAME>/FeatureGuard.git
      Credentials    : github-pat   (the credential you added above)
      Branch         : */main
      Script Path    : Jenkinsfile

    Under "Build Triggers":
      ✔ Poll SCM  →  Schedule: H/5 * * * *
        (Jenkins checks GitHub every 5 minutes for new commits)

    Save.

Step 4-D  Configure the Jenkins workspace path
───────────────────────────────────────────────
  The Jenkinsfile uses %WORKSPACE% and runs bat steps — this works natively on
  your Windows Jenkins agent with no extra configuration.

  Make sure the Jenkins agent has these on its PATH:
    ✔ python  (python --version → 3.11 or 3.12)
    ✔ node    (node --version  → 20+)
    ✔ npm
    ✔ docker  (Docker Desktop running; docker ps works from cmd.exe)
    ✔ kubectl (only for DEPLOY_TARGET=kubernetes)

  To check: Jenkins → Manage Jenkins → System → Global properties
  → Environment variables → add PATH entries if needed.

Step 4-E  Run the pipeline
───────────────────────────
  Jenkins → FeatureGuard → Build with Parameters

  Choose DEPLOY_TARGET:
    none       – runs all checks (tests, quality gate, smoke test) without deploying
                 ← start here the first time
    compose    – deploys the full stack to Docker Compose after all checks pass
    kubernetes – deploys to the K8s cluster after all checks pass

  Pipeline stages (all use Windows bat):
    1. Checkout             – checkout scm (SCM options) or workspace files (paste option)
    2. Install dependencies – python -m venv .venv, pip install, npm install
    3. Python tests         – pytest → reports\pytest.xml (published to Jenkins)
    4. Frontend tests+build – npm test && npm run build
    5. Train model          – download_data → validate_data → ml.train
                              QUALITY GATE: exits 1 if MAE/RMSE/R2 fail thresholds
                              → Jenkins marks build FAILED, no image is built
    6. Build Docker images  – featureguard-backend/frontend/nginx:%BUILD_NUMBER%
    7. Smoke test           – spins up a throw-away compose stack (-p fg-smoke),
                              curls /api/health and POST /api/predict, tears it down
    8. Deploy (compose)     – docker compose up -d with your real .env
       Deploy (kubernetes)  – kubectl set image + rollout status + auto-undo on fail
    9. Verify service health– curl /api/ready (compose) or rollout status (k8s)

  ON FAILURE: post { failure } block rolls compose back to PREV_TAG automatically
              (the image that was serving before this build started).

================================================================================
PHASE 5 – KUBERNETES  (Practical 9 + 10)
================================================================================

  Prerequisites: kubectl configured, Docker Desktop K8s enabled (or minikube).

Step 5-A  Tag and load images into the cluster
───────────────────────────────────────────────
  After building (Phase 3 or Jenkins), tag the images your K8s manifests expect:

  docker tag featureguard-backend:latest  featureguard-backend:v1
  docker tag featureguard-frontend:latest featureguard-frontend:v1
  docker tag featureguard-nginx:latest    featureguard-nginx:v1

  If using minikube:  eval $(minikube docker-env)   and rebuild inside it.

Step 5-B  Deploy with the helper script
────────────────────────────────────────
  cd deployment\kubernetes
  powershell -ExecutionPolicy Bypass -File deploy.ps1

  This applies manifests in numeric order:
    00-namespace-config.yaml  – Namespace + ResourceQuota + LimitRange
    10-postgres.yaml          – StatefulSet, Service, PVC
    20-backend.yaml           – Deployment (2 replicas), Service, liveness+readiness
    30-frontend.yaml          – Deployment, Service
    40-nginx.yaml             – Deployment, Service (NodePort 30080)
    50-monitoring.yaml        – Prometheus + Grafana Deployments + Services

Step 5-C  Access the application
──────────────────────────────────
  http://localhost:30080         (NodePort via Nginx)
  kubectl -n featureguard get pods        – should all be Running/Ready

  Liveness probe  → GET /health  (restarts the pod if it fails)
  Readiness probe → GET /ready   (removes from Service if DB or model unavailable)

Step 5-D  Rolling update demo
───────────────────────────────
  Build a new image:
    docker build -t featureguard-backend:v2 -f backend/Dockerfile .

  Trigger a rolling update (zero downtime because maxUnavailable: 0):
    kubectl -n featureguard set image deployment/backend backend=featureguard-backend:v2
    kubectl -n featureguard rollout status deployment/backend

Step 5-E  Rollback demo  (Practical 10)
─────────────────────────────────────────
  powershell -ExecutionPolicy Bypass -File deployment\kubernetes\rollback-demo.ps1

  The script demonstrates:
    1. Deploy a "bad" v3 image that fails readiness (simulated)
    2. Rollout stalls (old pods keep serving because maxUnavailable: 0)
    3. kubectl rollout undo deployment/backend  → returns to v2
    4. Verify pods are Running again

  NOTE: Kubernetes does NOT roll back automatically. The Jenkinsfile does it
  explicitly when `rollout status` times out (stage 'Deploy (kubernetes)').

PHASE 6 – MONITORING DETAIL  (Practical 7 + 8)
================================================================================

Prometheus metrics exposed at GET /api/metrics (or /metrics direct on port 8000):
  featureguard_prediction_requests_total    – all POST /predict calls
  featureguard_prediction_failures_total    – server errors on predict
  featureguard_validation_rejections_total  – inputs rejected by hard rules
  featureguard_drift_checks_total           – batch drift checks run
  featureguard_drift_alerts_total           – batches where drift was detected
  featureguard_request_latency_seconds      – histogram (method, path)
  featureguard_app_up                       – 1 while process alive
  featureguard_model_loaded                 – 1 when model.joblib is loaded

Prometheus scrape config: monitoring\prometheus.yml  (10s interval)
Grafana dashboard: monitoring\grafana\dashboards\featureguard.json
  → auto-provisioned on first start; no manual import needed.
  → shows: RPS, p99 latency, rejection rate, drift alert count, model metrics.

Grafana login: http://localhost:3000  admin / admin
