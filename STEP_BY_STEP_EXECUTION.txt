SECTION 2 – ML PIPELINE  (Practical 4 + 6)
================================================================================

STEP 4  Download the dataset
──────────────────────────────
  python ml\download_data.py

  Output:  data\raw\winequality-red.csv
  This file is DVC-tracked via data\raw\winequality-red.csv.dvc
  The CSV itself is git-ignored — only the .dvc pointer is committed.

STEP 5  Validate the data
──────────────────────────
  python -m ml.validate_data

  Expected output:  "Data validation passed for data/raw/winequality-red.csv"
  Exit code 1 = schema problem, do not proceed until this passes.

STEP 6  Train the model  (logs to MLflow, applies quality gate)
────────────────────────────────────────────────────────────────
  python -m ml.train

  What happens:
    1. Loads data\raw\winequality-red.csv
    2. Splits into train / test (80/20, random_state=42)
    3. Trains StandardScaler + RandomForestRegressor pipeline
    4. Evaluates MAE, RMSE, R2 on the test split
    5. QUALITY GATE: if R2 < 0.35 or RMSE > 0.75  →  exits with code 1
       (nothing saved, Jenkins will not build or deploy)
    6. Logs params + metrics to MLflow  (mlflow.db / experiment: featureguard-wine-quality)
    7. Registers model in MLflow registry  (alias: approved)
    8. Saves to models\  →  model.joblib, metadata.json, reference.csv

  Verify after training:
    dir models\
    →  model.joblib   metadata.json   reference.csv   .gitkeep

  To re-evaluate without retraining:
    python -m ml.evaluate

  To run the full DVC pipeline (only re-runs changed stages):
    dvc repro

STEP 7  View MLflow results  (Practical 6)
───────────────────────────────────────────
  mlflow ui --backend-store-uri sqlite:///mlflow.db

  Open http://localhost:5000
    Experiments tab  → featureguard-wine-quality  → click the latest run
    See: params (n_estimators, max_depth, test_size, random_state)
         metrics (mae, rmse, r2)
         artifacts (model/)
    Models tab  →  featureguard-wine-rf  →  version 1  →  alias: approved

  Press Ctrl+C to stop the MLflow UI when done.

STEP 14  Send drift traffic (simulate distribution shift)
───────────────────────────────────────────────────────────

  .venv\Scripts\python.exe -m scripts.simulate_traffic --mode drift --count 35

  What it does:

STEP 34  Run the pipeline

  DEPLOY_TARGET options:
    none       ← use this first time (runs all checks, no deploy)
    compose    ← deploys to Docker Compose after all checks pass
    kubernetes ← deploys to Kubernetes after all checks pass

  Pipeline stages:
    1  Checkout              pulls code from GitHub
    2  Install dependencies  python -m venv, pip install, npm install
    3  Python tests          pytest → reports\pytest.xml  (published in Jenkins)
    4  Frontend tests+build  npm test → npm run build
    5  Train model           download_data → validate_data → ml.train
                             QUALITY GATE: exits 1 if R2 or RMSE fail thresholds
                             → build marked FAILED, no Docker image is built
    6  Build Docker images   featureguard-backend/frontend/nginx:%BUILD_NUMBER%
    7  Smoke test            spins up throw-away compose stack (-p fg-smoke)
                             curls /api/health and POST /api/predict, tears it down
    8  Deploy                compose OR kubectl set image + rollout status
    9  Verify health         curl /api/ready OR kubectl rollout status

  ON FAILURE:
    post { failure } rolls compose back to PREV_TAG automatically.
